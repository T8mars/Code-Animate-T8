# 写出来的影像：用代码做视频

这份 SKILL 来自 B 站影片《写出来的影像》（约 18 分钟，每一帧都是 Claude 写的代码画出来的）。片子里用到的二十多种画法、骑自行车的鹈鹕、文字之城，源码都在开源仓库 https://github.com/T8mars/Code-Animate-T8 的 `film/`；口播对齐、时间线、字幕、混音脚本在仓库的 `tools/`。只拿到 SKILL 文件夹时，画法库当作做法说明来用。

找不到本文提到的 `template/`、`examples/`、`TOOLS.md` 时（例如这份 SKILL 是单独装的），先 `git clone https://github.com/T8mars/Code-Animate-T8`，用仓库里的 `skill/template/` 和 `skill/TOOLS.md`。

两条路径：
- **短片**（≤1 分钟、无口播或口播很短）：走「工作流程」1–7 步。已实测：一句话到 10 秒成片约 4.5 分钟（纯 CPU）。
- **长片 / 知识片**（有完整口播、剧本、配乐、双语字幕）：先走「开工前」，再走「工作流程」，口播部分按「长片：口播驱动」做。

## 什么时候用
- 「用演示场景的风格做个 10 秒片头」「做一段浮世绘风格的鹈鹕骑车」「把这段数据做成 20 秒动态图」「这是我的剧本和录音，做成代码动画片」
- 需要可复现、可改参数、能开源的画面；不需要真实人脸和真人表演（代码画不好，别硬做）

## 环境
- Node.js 18+、ffmpeg；在 `template/` 里运行 `npm install`，再运行 `npx playwright install chromium`（环境里已预装 Playwright 和 Chromium 的就跳过安装）
- 有独立显卡：渲染时加环境变量 `GPU=1`（Windows 用 D3D11；macOS 用 `GPU=metal`）。没有显卡也能渲，走 CPU 软件渲染，二维画布镜头还行，重着色器镜头慢 10–50 倍
- 长片另需 Python 3：numpy、soundfile、faster-whisper、pypinyin、jieba；可选 librosa（节拍）

## 开工前（长片必做，短片看情况）
先和用户对一遍**交付清单**，每一项问清楚或写下默认值，别等到最后才补：
1. 片长、比例、帧率（默认 1920×1080、30fps）
2. 字幕：中文 / 中英双语 / 不要；烧进画面还是单独 SRT（默认：双语烧录 + 三份 SRT）
3. 剧本的每一句都有录音吗？结尾的固定口播（如「我是 XX，我们下期见」）在不在剧本里？
4. 配乐来源和版权；片尾署名和参考资料
5. 开源：仓库地址，以及这个会话有没有推送权限（没有就提前说，交付时给用户打包好的提交 + 一键推送脚本）
6. 渲染在哪：云端几核、本地显卡型号；重着色器镜头（光线步进、体积、一镜到底）先估算每帧耗时 × 帧数，超过几小时就排给显卡
7. 交付方式：文件大小上限、分段传输方式

## 工作流程（每一步都要做，别跳）
1. **定风格和时长**。从「画法库」里挑一种或组合两种。时长换算成帧：30fps，10 秒 = 300 帧。
2. **先出样帧，再写运动**。每个镜头先只画一张关键帧（构图、配色、字号定死），截图给用户确认后再写动画。长片按幕出一张样帧拼图。改一张静帧比改一整段动画便宜得多。
3. **写 `template/scene.js`**（从示例改起最快）。页面必须提供两个全局函数，render.js / snap.js 会调用：
   - `window.initFilm = async () => {...}`：建 WebGL、编译着色器、**显式加载字体**（`await document.fonts.load('400 96px "JetBrains Mono"')`，只等 `document.fonts.ready` 可能等不到懒加载的字体）。
   - `window.renderFrame = t => {...}`：把第 t 秒画到 `#c` 画布（1920×1080）。必须是确定性的：同一个 t 永远画出同一帧，随机数用 `mulberry(seed)`，不要用 `Math.random()`。
   - 着色器：`const G = makeGL(1280, 720); G.add('名字', body)`。`body` 里自己写 `void main(){ ... O = vec4(col,1.); }`；可直接用内置 uniform `R`（分辨率）、`T` `P` `Q` `S`（浮点参数）和 `lib.js` 里 `GLSL_HEAD` 的函数（`gnoise`、`fbm`、`aces`、`hash1`）。自定义 uniform 自己声明，调用时 `G.run('名字', {T: t, P: 1, U: {myUniform: 0.5}})`，返回一个离屏 canvas，用 `ctx.drawImage(canvas, 0, 0, W, H)` 画到主画布。
   - 字体：`film.html` 里声明了 JetBrains Mono（400/700）、Space Grotesk（600）、Cormorant Garamond（500）；用别的字重会被浏览器合成，效果变差。
   - 长片（十几个以上镜头、有口播）不要自己写一个大 renderFrame，用 `template/shots.js` 骨架：scene 里只写 `shot(a, b, {draw, xin, grain, bloom, state})`，口播时间用 `setTimeline()` 载入后按 `LS(id)/LE(id)/GP(label)` 取，交叉溶解、有状态镜头重放（`syncState`）、角标都由骨架处理。示例见 `examples/shots_scene.js`，说明见 `TOOLS.md` 第 5–6 节。
   - 按下面的「画面规范」写。
4. **看静帧**：`node snap.js out_dir 0.5 2 4 6 8 9.5`，逐张看构图、字号、穿帮。
5. **看运动**（静帧看不出卡顿和抖动，这一步不能省）：
   - 每个有运动的镜头出一张接触表：`node contact.js shot.jpg <a> <b> 12`；快速运动、角色动作用连续帧 `--consecutive`，逐格看是否每帧都在动、每个姿态是否完整。
   - 每个角色出一张「全部姿态」接触表（例如拍翅 12 个相位），在成片尺寸下看，找断线、穿插、变形。
6. **渲染**：短片 `node render.js 0 10 out.mp4`（GPU 加 `GPU=1`）。长片用 `python3 rq.py 0 600 --out ../render/a1 --check`：按镜头表分段（不切开有状态镜头和交叉溶解）、`.done` 断点续跑、跑完自动拼接并跑 motion_check。2 核机器上并行几乎不提速（Chromium 单进程已占满两核），它在这里的价值是续跑和自动拼接；多核或有显卡时并行才真正提速。改了画面后旧的 `.done` 不会自动失效，要手动删掉对应段。
7. **交付前自查**：
   - `python3 motion_check.py out.mp4`（也能直接读分段的 concat 列表）：报告卡顿、抖动、静止超过 2 秒的区间。它只认节奏，刻意的定格、片门晃动、震屏也会报，逐条核对时间点，不是有意的就改。快速旋转不加模糊造成的「看着倒转」它查不到，要用 `contact.js --consecutive` 看。
   - 200% 检查：静帧裁 480×270 放大到 960×540 看锯齿、色带（`ffmpeg -i t_4.00.jpg -vf crop=480:270:720:400,scale=960:540 zoom.jpg`）。
   - 长片再跑 `voice_check.py` 和 `sub_check.py`（见下），并对照「开工前」的交付清单逐项打勾。
   - 最后一秒不要突然黑。

## 画面规范（这部片子用户挑出来的毛病，每一条都对应一个真实返工）
**运动**
- 离散步进（逐格动画、频闪、翻页、计数器）的每秒步数必须是帧率的整数约数：30fps 下只能 30/15/10/6/5 步。8 步/秒会变成 4、4、4、3 帧交替，看起来一卡一卡。用 `lib.js` 的 `stepAt(t, FPS, stepsPerSec)` 算当前格号。
- 快速旋转、快速移动的物体（转盘、车轮、甩动的镜头）用子帧运动模糊：`motionBlur(drawFn, t, n, shutter)`。
- 相机路径整段预先算好、平滑过再用，不要在 `renderFrame` 里按当前画面内容（地形高度、目标位置）临时决定，否则帧间跳变 = 镜头抖。相机的高度、位置、缩放一律经过 `lib.js` 的 `smoothTrack(fn, t0, t1, {dt, maxWin, passes})`（先采样、滑动最大值、再多遍平滑）。贴地飞行时取最大值的窗口要开够（3 秒左右），否则平滑后会略低于地形、钻进地面。
- 缓动用 `ease.inout` / `sstep`，不要线性起停；任何镜头静止不超过 2 秒，定格也要有轻微推拉或颗粒。

**造型**
- 剪影、角色一律用填充形状画。不要用「很细的描边 + 整体 scale」画翅膀、腿这类部件：缩放后线宽失真，在成片尺寸下像断了。
- 需要描边时，线宽按屏幕像素算：`screenLW(ctx, px)`，或用 `minLW` 保证缩小后不细于 1.5 像素（`pelican()` 默认 `minPx: 1.5`）。
- 同一画面里重复的小角色（转盘上的 12 只鸟）之间留出间距，填充造型比线稿占面积大，别挤成一圈。

**构图**
- 用命名的布局矩形（`const CANVAS = {x, y, w, h}`），主体用 `centerIn(drawFn, CANVAS)` 按实际绘制范围放进框里（`pelican()` 返回包围盒，任意绘制可用 `measureDraw` 量），不要用全局常量坐标。换布局时位置自动跟着走。
- 上屏文字 ≥36px，代码 ≥30px；高亮背景上的文字垫半透明暗底；文字永远不能镜像（贴在三维表面上的字按法线方向翻转）。

**健壮性**
- 搜索、匹配、查找失败时直接报错（`throw`），不要悄悄退回默认值。这部片子里文字之城定格的目标行没找到，代码退回了默认坐标，放大到了错误的那一行。
- 上屏的标签、注释从预先算好的列表里取（带迟滞，不闪烁），不要每帧临时挑选。

## 长片：口播驱动
仓库 `tools/` 里有这部片子用的全套脚本，可直接改用：

1. **听写**：faster-whisper（small 就够）带词级时间戳听写所有录音。
2. **对齐**：剧本和听写按拼音做模糊对齐（同音字识别错不要紧），单调动态规划，找出每句话在哪个录音的哪一段；同一句录了多遍取最后一遍或得分最高的一遍。
3. **切句**：切点放在两句之间的静音最低点，不要切在字上；前留 60ms、后留 150ms。
4. **补录替换**：用补录替换某一句后，必须检查**相邻两句**的片段：被替换的旧录音常常有半个字残留在前一句的结尾或后一句的开头（这部片子里就多出了一个「走」和一句「…墙上」）。
5. **口播校对**：每次重切之后都要跑，不能只抽听。
   - 先用逐句模式 `python3 voice_check.py script.txt voice/lines/ --terms "专有名词,…"`：报漏句、重复字词、首尾被切、切点没留白（旧录音残留多半靠这一条抓到）。
   - 再对整条口播跑一遍：`python3 voice_check.py script.txt voice_track.wav`，查漏句和重复。
   - `--terms` 只给专有名词，不要把整段剧本当提示词，否则识别会照着剧本猜，掩盖真错误。
   - 局限：Whisper 会把单字重复（「变变」）合成一个字，混进来的半个字也常常听不出。所以补录替换过的句子和它前后两句，仍要人工听一遍。
   - 录音和剧本不一致（口误、即兴改词）时，字幕以录音为准，和用户确认后改字幕文本。
6. **时间线**：画面时间线和口播时间线分开存。画面渲染好以后再改口播（重切、换句），只改口播时间线，画面时间线钉住不动；新句子落进已有的空隙里。否则一句话变长 0.5 秒，后面所有镜头都要重渲。
7. **字幕**：`python3 subs.py script.txt timeline.json en_subs.py --out subs/film --terms "专有名词,…" --words words.json`
   - 中文按标点切，每条 ≤20 字；长句用 jieba 只在词边界断，不拆《》书名和 `--terms`；间隔 <1 秒的条合并。有词级时间（`--words`）时字幕跟着实际出字时刻走，没有就按字数比例估。
   - 双语：英文按中文的每一条单独翻译，存成「中文条 → 英文」字典；缺的条目会全部列出并写一个待填模板。输出双语 ASS（中文在上、英文在下，半透明底框）和中英、中文、英文三份 SRT。
   - 然后 `python3 sub_check.py subs/film.ass --lines timeline.json`：查超长行、词中间断开、引号被拆到两条、显示时间太短读不完、字幕和口播错位、英文缺行。
8. **混音**：口播高通 + 轻压缩；音乐在口播出现时压低约 8 dB（起音 60ms、释放 450ms）；切点和冲击点对齐实测节拍（librosa beat_track），误差不超过一帧；整体响度 -14 LUFS（B 站 / YouTube）。纯画面段不要全静音，至少垫一层环境声或音乐。
9. **拼接**：各段 concat，烧字幕，混音轨对齐，`-movflags +faststart`。

## 经验（片子里真实踩过的坑）
- 无显卡环境：`render.js`/`snap.js` 已默认加 `--disable-accelerated-2d-canvas --disable-gpu-rasterization`（二维画布快 20 倍以上），并用 `canvas.toDataURL` 管道给 ffmpeg 抓帧；自己另写渲染脚本时照抄。重着色器镜头可以降到 960×540 渲再放大（`makeGL(960, 540)`），步数减半，肉眼差别很小。
- 光线步进的山顶缺块：求交起点的包围高度要留够余量（`top = AMP*1.4`）。
- 有状态的镜头（粒子、流线、数据混合）：从镜头起点按帧号重算，分段渲染不能把这种镜头切开（分段脚本里设成单独一整块）。
- 分段渲染用 `.done` 标记断点续跑；改了某个镜头，只删掉和它时间重叠的块重渲，其余不动。
- Windows 本地渲染：路径用 `pathToFileURL`；`.bat` 文件只用 ASCII 字符、CRLF 换行。
- 大文件分段传输时，第一段以 mp4 文件头开头，可能被中转环节当成视频改写：把第一段先打成 zip（不压缩）再传，合并脚本里先解压，交付后核对总字节数或 md5。
- 用户反馈的问题，修完后用同样的检查工具复核一遍（听写、motion_check、接触表），再交付。
- 有状态镜头的快照要自己深拷贝，1080p 一张约 8MB；不提供快照时，跳到长镜头后段要从头重放。
